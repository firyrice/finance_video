# A Roll 附加方法论（storyboard_plan.md · 仅当本片有 A Roll 输入时加载）

本文件是 [storyboard-plan.md](storyboard-plan.md) 的**可选叠加层**。默认账号无真人出镜、全 `cloud_only` 三档，不读本文件。**仅当用户明确声明本片有 A Roll 输入**（要露脸拍 / 有主播真人口播素材 / 加 A Roll）时，才在标准三档之外启用这里的两档，并按本文判定哪些分镜露脸。用户没提，就当没有——照常三档，别自作主张加露脸镜。

## A. A Roll 是什么：b-roll 的特化子类

视频术语里 A-roll / B-roll 本就是一对：**A-roll = 主角露脸的主线镜头，B-roll = 补充空镜/素材**。所以 A Roll 不是新物种，而是把「真人出镜」这一种素材来源，从原来模糊的「主播口播实拍」描述里拎出来单独成档，让它有专属的拍摄规格承载位，花生 AI 也能靠类型字段直接识别哪些分镜要拍真人，而不是猜描述里有没有「主播」两个字。

## B. 两档 A Roll 画面类型（与两档 b-roll 对齐）

在标准三档（`b-roll` / `b-roll+mg` / `mg_frame`）之外，新增两档，落法与 b-roll 完全对齐：

- **`a-roll` —— 纯露脸口播，无叠加**：主播正面对镜口播，无 MG。用于强观点、态度落点、免责声明这类「话就是全部、脸就是重点」的镜。
- **`a-roll+mg` —— 露脸 + 轻叠加**：主播露脸，叠一层轻量 MG（互动图标、单枚高亮数字/标签、评论气泡），MG 不抢戏、只做点缀。用于品牌锚、互动 CTA、以及露脸时想顺手强调一个单点的镜。

> 注意：A Roll 的底层是真人素材，不是 `cloud_only` 检索素材。凡标 `a-roll` / `a-roll+mg` 的分镜，`source` 位写 `a_roll`（表示这镜要拍真人，不走云端检索），其余分镜照常 `cloud_only`。

## C. 核心判定问句

对标主文件三档的「这一镜只用实拍会不会平/看不懂」，A Roll 的判定问句是：

> **「这一镜，观众需要『看到是谁在说』吗？需要我这个人站出来表态、担责、拉近距离——就上 A Roll；只需要信息本身——就交给素材和 MG。」**

一句话：**讲信息 → b-roll / MG；讲态度、讲「我」→ A Roll。**

## D. 正面清单：六类「人在场」时刻（满足其一即上 A Roll）

1. **品牌锚 / 人格开场**（固定语）——账号人格的第一声。→ 一般 `a-roll+mg`（可叠品牌片头元素）。
2. **转场 / 悬念 / 卖关子**——设问、留白、抛钩，露脸把钩子「递」到观众眼前。→ `a-roll`。
3. **态度 / 情绪落点**——加重、克制、讽刺、客观平衡，微表情和语气只有脸能传。→ `a-roll`。
4. **第一人称观点 / 判断 / 表态**——「我」「我不」「我给你」「我提醒你」，A Roll 最核心的用武之地。→ `a-roll`。
5. **互动 / CTA 结尾**——求评论求关注，露脸才有「求人」的温度。→ `a-roll+mg`（叠点赞/关注/评论图标）。

## E. 反面清单（别硬上 A Roll）

- **纯数据 / 纯事实陈述**：数据砸屏、算式、多主体关系、清单——画面本身在传递信息，露脸会覆盖掉信息。这些是素材 + MG 的主场。
- **连续多镜堆露脸**：主播一直对着镜头说话会枯燥、显说教。A Roll 是锚点不是主体，**必须和素材 / MG 交替呼吸**。
- 任何「画面本身在传递信息」的地方。

## F. 频率与节奏

- A Roll 是**锚点不是主体**，大致每个逻辑章节的开头或收尾各一次即可，避免连续两三镜都是脸。
- 显式统计**露脸密度**：A Roll 分镜数 / 总分镜数，**合理值 20%~30% 上下**。低于此人格感不足，高于此说教感重、节奏拖。定完类型回头扫一遍，超了就把部分露脸镜降级回 b-roll / MG。
- 判定顺序（接主文件步骤四之后）：先按正面清单五类时刻标出候选 A Roll → 用反面清单剔掉不该露脸的 → 按频率 20%~30% 收敛 → 剩下的照主文件三档逻辑走。

## G. A Roll 分镜的画面描述怎么写

A Roll 需要单独的**拍摄规格**（这正是把它从 b-roll 拎出来的意义），画面描述里交代：

- `a-roll`：写清 **景别**（近景/半身/特写）、**机位**（正面对镜/侧四十五度）、**情绪标签**（克制陈述/语气加重/反讽/客观平衡）、是否用**提词器**。一句话说清「主播以什么状态说这句」。
  - 例：「主播半身正面对镜，提词器辅助，语气克制不带情绪——念到『那是情绪』时微微摇头。」
- `a-roll+mg`：先写上面的拍摄规格（同 `a-roll`），再写**叠加的轻量 MG 层**是什么、怎么配合（互动图标何时弹、单枚数字/标签叠在画面哪侧、念到哪句浮现）。MG 只做点缀，别盖脸、别抢话。
  - 例：「主播半身正面对镜，语气热络收束；画面右下依次弹出点赞/收藏/关注图标，末尾左上叠『下期：华友钴业』预告小卡片。」

## H. 输出模板增量

启用 A Roll 时，在主文件模板基础上做两处增量：

1. **分镜行的画面类型枚举扩为五档**：`a-roll` / `a-roll+mg` / `b-roll` / `b-roll+mg` / `mg_frame`；A Roll 分镜的 `source` 位写 `a_roll`，其余照常 `cloud_only`。
   - 行格式示例：`S39 ｜ a-roll ｜ a_roll ｜「口播原句，一字不改」`
2. **成片需求 §🎥 素材要求**里加一行 `A Roll 说明`：本片有真人出镜，列出要拍真人的分镜号清单 + 整体露脸密度（如「A Roll 分镜：S02/S39/S48/S51/S63/S65…，露脸密度约 25%」），方便拍摄侧一次性看清要拍哪些。

> 其余（Method B 五步、口播稿逐字不改、MG 画风双层模型、cloud_only 检索规则）全部沿用主文件，不重复。
